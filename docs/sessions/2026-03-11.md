# Session — March 11, 2026

## Summary
Fixed product card size display bug on featured products (homepage).

## Problem
The featured product cards on the homepage showed "Size 0" instead of the actual size value (e.g., XL, L, M). The product page displayed size correctly, but the product card snippet did not.

## Root Cause
The product card was reading from `product.metafields.custom.size` which held a stale value of `0`. The actual size data is set via Shopify's **Category metafields** (under the product taxonomy for clothing), which uses the `shopify` namespace — not `custom`.

Category metafields are stored as metaobject references, so accessing the display value requires:
```liquid
product.metafields.shopify.size.value  →  list of metaobject refs
_sizes.first.system.handle | upcase    →  "XL", "L", "M", etc.
```

## Fix

**File changed:** `theme/snippets/product-card.liquid`

Before:
```liquid
{% if product.metafields.custom.size %}
  Size {{ product.metafields.custom.size }}
{% endif %}
```

After:
```liquid
{% assign _sizes = product.metafields.shopify.size.value %}
{% if _sizes != blank %}
  {% assign _s = _sizes | first %}
  Size {{ _s.system.handle | upcase | default: _s }}
{% endif %}
```

## Key Learnings
- Shopify category metafields (Size, Color, Fabric, etc.) live under `product.metafields.shopify.*` — not `custom.*`
- Category metafields return metaobject list references, need `.value` then `.first.system.handle` for the human-readable value
- `product.options_with_values` does NOT work inside `{% render %}` snippets when the product comes from a collection loop
- In Liquid, `0` is truthy — `{% if 0 %}` evaluates to true, so a metafield with value `0` still passes a basic if check

## Files Changed
- `theme/snippets/product-card.liquid` — Size display fix (metafield namespace + metaobject access)
